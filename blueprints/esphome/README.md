# ESPHome

ESPHome is an open-source system to control ESP8266/ESP32 microcontrollers through simple yet powerful YAML configuration files and manage them remotely through home automation systems. This template runs the **ESPHome Device Builder** — the web dashboard where you create, edit, validate and compile custom firmware for your devices and install it wirelessly (OTA), no command line needed.

## How this deployment works

This template deploys ESPHome's **official Docker image** (`ghcr.io/esphome/esphome`), a single container serving the dashboard on port 6052:

- All device configuration files, build artifacts and the PlatformIO toolchain cache live in the `esphome_config` volume mounted at `/config`, so everything survives container restarts and updates.
- The dashboard is protected by a login. The username is `admin` and the password is **generated by Dokploy at deploy time** — find it in the stack's environment variables in Dokploy (`ESPHOME_PASSWORD`) after deploying.
- The container runs with regular bridge networking behind Dokploy's proxy (upstream recommends host networking, which a Dokploy domain cannot use). The dashboard still works fully; see the notes below for what that changes.

## First run

1. Open your Dokploy domain and log in with username `admin` and the generated `ESPHOME_PASSWORD` from your stack's environment in Dokploy.
2. Click **New device**, give it a name and pick your board — the wizard creates its first YAML configuration.
3. Edit the configuration in the browser, then choose **Install**. For a brand-new device, use **Plug into the computer running the browser** (Web Serial) for the very first flash; every later update installs wirelessly (OTA).
4. The first compile downloads the PlatformIO toolchains into the `/config` volume — it can take several minutes. Later compiles reuse the cache and are much faster.

## Notes

- **Discovery:** without host networking the dashboard cannot use mDNS, so devices do not appear by their `.local` names automatically. It tracks device status by ping instead, and OTA installs work against the device's IP address — give your devices static IPs (or DHCP reservations) and use `use_address` in a device's YAML if needed.
- **USB flashing from the server is not available** in this deployment (no serial device passthrough); first-time installs happen over Web Serial from your own computer, exactly as upstream's Docker guide describes for non-host setups.
- Keep the dashboard behind its login — anyone with access can edit device configurations and install firmware. Change the username by editing the `ESPHOME_USERNAME` environment variable in the compose file.
