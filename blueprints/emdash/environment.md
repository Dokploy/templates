# Environment variables

Checked against [EmDash 1.4.0](https://github.com/emdash-cms/emdash/tree/10beb8c5a99e41c3a8554b09ac5123c4dddc8d11), its root Dockerfile, Blog Astro configuration, and runtime environment readers. Compose passes the variables below into the process; editing an unused variable in Dokploy does not change the compiled Astro configuration.

## Operator settings

| Variable | Template value | Meaning |
| --- | --- | --- |
| `EMDASH_SITE_URL` | `https://<generated-domain>` | Required public HTTP(S) origin, without a path. Use the final HTTPS origin for production setup, passkeys, CSRF, and absolute URLs. Keep it aligned with the Dokploy domain. |
| `EMDASH_ENCRYPTION_KEY` | Empty | Optional for the stock site. Required for encrypted plugin-secret settings. Use `npx --yes emdash@1.4.0 secrets generate`; the format is `emdash_enc_v1_` plus 43 canonical base64url characters encoding 32 random bytes. For rotation, list the new key first followed by older keys separated by commas. Preserve every key still used by saved secrets. |

No administrator password, database password, or provider key is generated by this template. The setup wizard creates the administrator's passkey. EmDash generates its preview HMAC secret and commenter-IP salt into SQLite on first use. Sessions and API tokens are generated by the application.

## Fixed Compose and build values

| Setting | Value | Meaning |
| --- | --- | --- |
| `HOST` / `PORT` | `0.0.0.0` / `4321` | Node listener, matching routing and the health check. |
| `EMDASH_TRUSTED_PROXY_HEADERS` | `x-forwarded-for` | Trust the controlled Traefik proxy for client IPs. Keep the app isolated from direct/untrusted connections. Change Compose if another proxy policy is needed. |
| Database | `file:./data/data.db` | Fixed by the upstream Dockerfile's Blog configuration. `DATABASE_URL` and `DATABASE_PATH` do not switch this build's database. |
| Media | `./uploads` | Fixed local adapter with public route `/_emdash/api/media/file`. S3 variables alone do not switch storage. |
| `NODE_OPTIONS` | Build-stage `--max-old-space-size=4096` | Upstream compiler heap allowance; not a runtime memory reservation. No secrets are passed as build arguments. |

The upstream Dockerfile has no argument to supply the public origin during compilation. `EMDASH_SITE_URL` is supplied at runtime; local media therefore uses original files rather than build-configured image optimization. Change the upstream project/build if you need that optimization or another theme.

## Optional upstream controls

These are not generated or forwarded by this template. To use one, add an explicit Compose environment mapping and redeploy after reading its upstream contract:

- `EMDASH_PREVIEW_SECRET`: overrides the database-generated preview secret. Changing it invalidates existing preview links.
- `EMDASH_IP_SALT`: overrides the database-generated commenter-IP salt. Changing it resets rate-limit continuity. Legacy `EMDASH_AUTH_SECRET` is only a salt fallback, not a login requirement.
- `EMDASH_MIGRATIONS_MODE`: defaults to `auto`; `check` refuses pending migrations, and `manual` leaves migration management to the operator. Do not change it without an explicit migration procedure.
- `EMDASH_ALLOWED_ORIGINS`: comma-separated HTTP(S) origins for advanced authentication deployments, subject to the passkey relying-party domain rules. The single-domain template needs none.
- `EMDASH_TURNSTILE_SECRET_KEY`: optional Cloudflare Turnstile secret for public comments. Unset means no Turnstile enforcement. Also configure the matching public widget/site key in your theme before enabling it; a secret alone rejects comments that have no valid token.

Email, OAuth, AI, remote database/storage credentials, and plugin settings are optional integrations, not installation requirements. Many also require installing/configuring the corresponding adapter or plugin and rebuilding. See [instructions.md](instructions.md) before adding them. Cloudflare bindings and Wrangler settings do not apply to this Node build.

`EMDASH_QUERY_LOG=1` enables diagnostic query logging; `EMDASH_PSEUDO_LOCALE=1` is a development UI test option. Both are unset here. Development bypass/reset/email endpoints are compiled out of production and are not setup mechanisms. `EMDASH_URL`, `EMDASH_TOKEN`, and `EMDASH_HEADERS` are CLI client inputs, not server deployment settings.
