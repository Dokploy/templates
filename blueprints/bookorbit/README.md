# BookOrbit

BookOrbit is a self-hosted reading space: organize, track, and read your personal book library from your own server, with OPDS feeds and KOReader and Kobo sync.

- 🌐 Website: https://bookorbit.app
- 📚 Docs: https://bookorbit.app/installation
- 💻 Source: https://github.com/bookorbit/bookorbit

## Deployment

This template runs two services:

- **app** — BookOrbit `3.8.0` (the latest stable release), served on your domain.
- **postgres** — PostgreSQL 18 with the pgvector extension (`pgvector/pgvector:pg18`), which BookOrbit requires. The app waits for the database healthcheck before starting.

All secrets are generated by Dokploy at deploy time: the database password, the JWT secret, and the setup bootstrap token. `APP_URL` and `CLIENT_URL` are set automatically from your domain, and the app requires HTTPS, which the domain provides.

## First-run setup

BookOrbit has no preset administrator account. On first launch, open your instance and complete the setup form to create the administrator account. The form asks for a **setup token**: this is the generated `SETUP_BOOTSTRAP_TOKEN` value, which you can find in Dokploy in this service's environment after deploying. The token only guards this first account creation.

## Storage

- `books` — your library files, mounted at `/books`. Add your books there, or create libraries from the app's own folder picker.
- `app_data` — app-managed data (covers, metadata, reading state), mounted at `/data`.
- `postgres_data` — the database.

## Notes

- The optional read-aloud and text-to-speech worker services from the upstream compose file are not included; upstream ships them as opt-in profiles.
- If your book files are owned by a user other than UID 1000, change `PUID` and `PGID` in the environment to match — mismatched ownership is the most common cause of first-scan permission errors.

## Tested on Dokploy
